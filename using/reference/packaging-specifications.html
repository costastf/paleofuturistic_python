Packaging specifications

What a project generated from this template does about each specification on the PyPA specifications index, for anyone deciding whether the template fits. Every generated project ships its own copy of this table, written for that project's settings, under Developer → Reference → Packaging specifications.

"Gate" means a check that fails ./workflow.cmd preflight, and so the pre-push hook and the pipeline. The template's own test suite (tests/test_packaging_specs.py) builds a generated project and checks its sdist and wheel against these specs on every template change.

Summary

Spec Generated project Where it is enforced Knob dependence
Names and normalization project_slug is a valid import name and project name project_slug validator at generation —
Core metadata Metadata 2.4 from [project], README as text/markdown Gate: twine check --strict —
Version specifiers PEP 440; commitizen version_scheme = "pep440" Gate: validate-pyproject —
Dependency specifiers PEP 508 everywhere Gate: validate-pyproject —
pyproject.toml All metadata and tool config in one file, static (no dynamic) Gate: validate-pyproject, per commit and per push —
Dependency groups All tooling in groups; dev includes the rest Gate: validate-pyproject (includes resolve) —
Inline script metadata How-to for standalone scripts — —
Well-known project URLs [project.urls] with well-known labels Template tests repository_url; Documentation needs GitHub + Pages
glob patterns license-files = ["LICENSE"] uv build fails on an unmatched pattern absent when license=None
License expression SPDX license, no License :: classifier Gate: validate-pyproject (syntax) absent when license=None
Source distribution format uv build sdist Gate: twine check --strict —
Binary distribution format py3-none-any wheel with py.typed Gate: check-wheel-contents, twine check --strict —
Platform compatibility tags Pure Python uv_build —
Entry points None by default; how-to for scripts and plugins Gate: validate-pyproject, once added —
Index hosted attestations PEP 740 attestation per file, uploaded via Trusted Publishing release.attest in the publish job both hosts; GitLab needs gitlab.com
Simple repository API uv as client; how-to for private indexes — —
.pypirc Not used; gitignored .gitignore —
File yanking How-to PyPI —
Project status markers How-to PyPI —
Recording installed projects Installer-side; uv Template tests install the wheel and check RECORD, INSTALLER —
Direct URL data structure Installer-side; uv Template tests check direct_url.json —
Virtual environments uv-managed .venv — —
Externally managed environments Never installs into a system interpreter — —
build-details.json Interpreter-side; nothing to do — —
pylock.toml develop.pylock exports reports/pylock.toml — —
PyPA schemas Used through validate-pyproject Gate: validate-pyproject —

Known gap

A License :: classifier added next to the license expression passes every gate: the spec says tools should refuse it, and uv_build does not. Generated projects ship without one.
