# ADR-0012: The SBOM ships inside the wheel

- **Status**: accepted
- **Date**: 2026-03-30 (SBOM generated), 2026-05-28 (inside the wheel)
- **Record written**: 2026-11-11 (backfilled)

## Context

A bill of materials produced beside a release has to be correlated with it afterwards: stored
somewhere, named after the version, found again when someone asks "are we affected by CVE-X?".
The first version of this template generated one with the `cyclonedx-bom` CLI and uploaded it
to a Dependency-Track server, which tied every project to one SCA platform and one set of
credentials.

## Decision

`_CI/tasks/sbom.py` composes a CycloneDX 1.7 SBOM with `cyclonedx-python-lib` and writes it to
`src/<package>/sbom.cdx.json`. That path is inside the package data tree, so `uv build` ships
it inside the wheel without any packaging configuration. It covers four sources, distinguished
by scope: runtime dependencies (`required`), dependency groups (`optional`), the vendored CI
tooling (`excluded`) and the chosen host's pipeline components (`excluded`), joined by a
two-level dependency graph through a synthetic build-environment component. Each component
carries a licence, a lockfile hash where there is one, and a link to its upstream page. The
file is validated against the CycloneDX schema and regenerated by `secure.sbom` as part of
every `build`.

## Consequences

- A consumer extracts it with `unzip -p <wheel> <package>/sbom.cdx.json` or
  `importlib.resources`. No separate artefact, no correlation step.
- The SBOM is a build input, so it is deterministic from the tree, and the dependency audit is
  deliberately not bundled with it (ADR-0013).
- Composing it costs about a second of imports, which is why `secure.py` imports `sbom.py`
  lazily and the launcher stays fast for every other task.
- The SBOM's VCS reference is read from `origin`, so CI checkouts must leave no credential in
  the remote URL; the publish job's checkout persists none.
- Which SCA platform reads the SBOM is the organisation's call. The Dependency-Track upload was
  removed in November 2026.
